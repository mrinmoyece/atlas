# Learning path

This repository is organised as a curriculum. Each phase teaches one idea,
points at the code that implements it, names the failure it prevents, and
gives you an exercise that breaks something on purpose. Work in order.

Run `make demo` first so you have seen the whole system move before you
start reading it.

---

## Phase 1 — Context engineering

**Idea.** Orchestration is the easy part. The hard part is deciding what to
keep, what to drop, and how to stop old context polluting new answers.

**Read.** `src/atlas/context/budget.py`, `src/atlas/context/compaction.py`

**The failure it prevents.** Naive truncation orphans a `ToolMessage` whose
originating `AIMessage` was dropped. Most providers reject that outright, so
your agent starts 400-ing under exactly the long conversations you built it
for.

**Key decisions to be able to defend**
- why compaction runs immediately *before* every model call, not at the end
  of a loop iteration
- why dropped turns are summarised rather than deleted, and why the summary
  preserves *which tools were already used*
- why a single oversized message is truncated rather than allowed to evict
  the whole history

**Exercise.** Set `keep_recent=1` and run `pytest tests/test_context.py`.
Then remove `_pull_back_to_safe_boundary` and watch
`test_compaction_never_orphans_tool_results` fail. That test is the shape of
a real production incident.

## Phase 2 — Memory that earns its cost

**Idea.** LLMs are stateless. "The agent learns" is a claim about
*engineering*, and it must be measured, because memory has real costs:
tokens, and the risk of anchoring on a pattern that doesn't apply.

**Read.** `src/atlas/memory/` (all of it), then `docs/MEMORY.md`

**The failure it prevents.** Three, actually: memorising model prose turns
memory into a hallucination amplifier; retrieval without a relevance floor
injects confident garbage; unsmoothed procedural memory locks onto a lucky
1-for-1 strategy and makes the agent *worse* than having no memory.

**Key decisions**
- four tiers (working / episodic / semantic / procedural) and what belongs
  in each
- why lessons come only from structured `Finding` objects carrying evidence
- recency decay applied at retrieval, not deletion at write time
- Laplace smoothing in `StrategyStats.score`
- in the A/B harness, why scoring happens *before* learning

**Exercise.** Delete the `min_score` floor in `SemanticMemory.search` and
run `make memory-ab`. Then set `prior_weight=0` in `StrategyStats.score` and
see `test_laplace_smoothing_beats_lucky_single_success` fail.

## Phase 3 — Protocols: MCP and A2A

**Idea.** MCP is how an agent talks to *tools*; A2A is how an agent talks to
other *agents*. Implementing both sides of MCP is what separates protocol
understanding from SDK usage.

**Read.** `src/atlas/mcp_layer/server.py`, `client.py`, `src/atlas/a2a/cards.py`

**The failure it prevents.** A remote MCP server's tool descriptions are
attacker-controlled text that you are about to paste into a model's prompt.
Unsanitised, that is prompt injection with extra steps.

**Key decisions**
- allowlist by server *and* tool name; discovery is not permission
- namespacing `server::tool` so a remote tool cannot shadow a local one
- sanitising descriptions, and *logging* that sanitisation happened
- routing by A2A capability tag rather than a hard-coded agent roster

**Exercise.** Write a fake MCP session that advertises a tool called
`read_file` with a hostile description. Confirm it neither shadows the local
tool nor reaches the prompt intact.

## Phase 4 — Multi-agent orchestration

**Idea.** Parallel fan-out with **context isolation**. Specialists run
concurrently, keep their own transcripts, and return only findings plus a
summary.

**Read.** `src/atlas/graph/state.py` (reducers first), then `build.py`

**The failure it prevents.** Wrong reducers silently drop results from
concurrent branches — you lose findings and never see an error. And without
isolation, four transcripts land in shared state and every later step pays
for all of them, which is why naive multi-agent costs more and performs
worse than a single agent.

**Key decisions**
- which fields accumulate (`operator.add`), which sum, which merge, which
  are last-write-wins, and why each
- why a specialist failure records an error and continues instead of failing
  the run
- why the final verdict is *derived from structured findings* rather than
  generated by a model

**Exercise.** Change `findings` from `Annotated[list, operator.add]` to a
plain `list` and run `test_reducers_accumulate_from_all_parallel_specialists`.
Note that nothing crashes — findings just quietly vanish.

## Phase 5 — Pattern science

**Idea.** "Which agent pattern should we use" is an empirical question, not
folklore. Implement four, measure them on identical inputs.

**Read.** `src/atlas/patterns/` (base first), then `benchmarks/RESULTS.md`

**Key decisions**
- ReAct's repeat-call detection (the tool loop is the classic runaway)
- Plan-and-Execute's re-anchoring guard against plan drift
- Reflexion's critique/revise split, and why it trades recall for precision
- ReWOO's two-model-call structure and what it structurally cannot do

**Exercise.** Add a fifth pattern (Tree-of-Thoughts is a good candidate),
register it in `PATTERNS`, and get it into the benchmark table. If your
pattern needs more model calls than the script provides, you will meet the
scripted-model routing design from Phase 6.

## Phase 6 — Evaluation as infrastructure

**Idea.** Agent behaviour is code, so it belongs in CI. Ground truth makes
quality a number; a deterministic model makes that number reproducible.

**Read.** `src/atlas/evals/scoring.py`, `judge.py`, `runner.py`,
`evals/golden/ground_truth.yaml`, `src/atlas/llm/scripted.py`

**Key decisions**
- planted ground truth + **traps** (an agent that reports everything gets
  perfect recall — traps are how you catch it)
- micro vs macro averaging on an imbalanced fixture set
- the deterministic groundedness check (does the cited file *exist*) — no
  judge needed to catch the worst hallucination class
- LLM-judge bias controls: position swap, neutral labels, anchored rubric
- three CI tiers: smoke on every PR, gate on merge, extended nightly

**Exercise.** Add a third fixture repo with its own planted issues and
traps, extend `ground_truth.yaml` and `scenarios.py`, and check whether the
gate thresholds in `GATES` still hold.

## Phase 7 — Production hardening

**Idea.** An agent platform spends money on every request and reads
attacker-authored content. Both are security properties.

**Read.** `src/atlas/security/`, `src/atlas/api/app.py`,
`docs/SECURITY_MODEL.md`

**Key decisions**
- deny-by-default auth; hashed keys; constant-time comparison
- RBAC where *spending money* is the privileged action
- pre-flight spend budget (checking after the run tells you the money is
  already gone)
- hash-chained audit log
- why the body-size limit is pure ASGI rather than `BaseHTTPMiddleware`
  (see the comment — it only breaks once you add SSE)
- secret redaction at the logging boundary, not at call sites

**Exercise.** Remove the `nonlocal replayed` / disconnect logic reasoning
from the ASGI body limiter by reverting to a buffering
`BaseHTTPMiddleware`, then run
`test_streaming_emits_specialist_then_complete`. Understanding why that
fails is worth more than the fix.

## How to know you've actually learned it

You can answer these without looking:

1. Why does a specialist return only findings and a summary?
2. What breaks if compaction drops an `AIMessage` but keeps its `ToolMessage`?
3. Why is a 1-for-1 strategy dangerous in procedural memory?
4. Why does the clean fixture repo contain issues that are *not* bugs?
5. When would you deliberately choose ReWOO despite its worse F1?
6. What does the micro/macro averaging difference do to the headline number?
7. Why is `/metrics` authenticated here when it usually isn't?
